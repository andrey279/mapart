# MapArt Studio

Консольный преобразователь и настольный редактор мап-арта для Minecraft Java Edition. Программа подбирает цвета блоков под изображение, создаёт PNG-превью и экспортирует постройку в `.nbt`, которую можно открыть в Litematica. Работает с плоскими картами **2D** и высотными лестницами **3D**.

[English](README.en.md) · [Скачать сборки](https://github.com/andrey279/mapart/releases) · [Сборка из исходников](BUILD.md) · [Сообщить об ошибке](https://github.com/andrey279/mapart/issues)

Одна карта — **128 × 128 пикселей**, один пиксель результата — один блок поверхности. Например, 5 × 3 карты дают изображение 640 × 384. CLI, Windows GUI и Linux GUI используют общие алгоритмы, палитры и JSON-профили. Обработка локальных изображений, генерация QR и экспорт выполняются на компьютере; интернет нужен для скачивания изображений через `-links`.

## Возможности

- PNG, JPEG, WebP, GIF, BMP и TIFF на входе; PNG на выходе. Для GIF обрабатывается один кадр.
- Подбор цвета в Lab с CIEDE2000 или в RGB; Floyd–Steinberg, упорядоченный дизеринг и режим без дизеринга.
- Девять пресетов, цветокоррекция, обрезка, повороты, отражения, масштабирование и ручные маски.
- 60 материалов с разными базовыми цветами карты: до 60 цветов в 2D или 180 высотных оттенков в 3D. Материалы можно выбирать вручную.
- Общая схема `.nbt` или ZIP со схемами отдельных карт, список материалов CSV, параметры размещения JSON и превью карты в игре.
- Настольный GUI с редактором исходника, рисованием по готовой карте, отменой и возвратом правок.
- Генератор QR-карт из текста или ссылки с проверкой чтения, оформлением и логотипом.
- Пакетная конвертация папки или списка URL, HTML-сравнение пресетов и диагностические изображения в CLI.

Программа создаёт файлы постройки и изображения. Она не размещает блоки в мире, не подключается к игровому серверу и не создаёт файлы игровых карт `map_*.dat`.

## Установка и запуск

Готовые сборки появляются в [Releases](https://github.com/andrey279/mapart/releases) после публикации релиза владельцем. Если релизов ещё нет, соберите программу из исходников. Для сборки требуется **Go 1.26 или новее** согласно `go.mod`.

```bash
git clone https://github.com/andrey279/mapart.git
cd mapart
go mod download
go build -o mapart .
```

На Windows: `go build -o mapart.exe .`. Команды ниже используют `./mapart`; в PowerShell замените его на `.\mapart.exe`. В примерах `photo.jpg`, `source.png` и другие изображения — ваши собственные файлы, они не поставляются с проектом.

| Платформа | Консоль | Графический интерфейс |
| --- | --- | --- |
| Windows amd64 | `mapart.exe` с аргументами | Нативное окно Walk/Win32; `mapart-gui.exe` или `mapart.exe -gui` |
| Linux | `mapart` | Fyne; отдельная сборка с `-tags gui` |
| macOS | `mapart` | Fyne можно собрать с `-tags gui`; готовые пакеты workflow содержат CLI |

### Windows GUI

Откройте `mapart-gui.exe` двойным щелчком. `mapart.exe` без аргументов также открывает GUI. Окно можно запустить сразу с файлом и настройками:

```powershell
.\mapart.exe -gui -i photo.jpg -preset portrait -x 3 -y 4
```

[build.ps1](build.ps1) собирает консольный и оконный исполняемые файлы. В проект включён ресурс manifest; `-RefreshManifest` пересоздаёт его при необходимости.

### Linux GUI

На Debian/Ubuntu установите компилятор и графические библиотеки:

```bash
sudo apt-get install -y build-essential pkg-config libgl1-mesa-dev \
  libxcursor-dev libxrandr-dev libxinerama-dev libxi-dev libxxf86vm-dev \
  libwayland-dev libxkbcommon-dev wayland-protocols

go build -tags gui -o mapart-gui .
./mapart-gui
```

Для CLI эти библиотеки не нужны. GUI запускается в графической сессии с доступным `DISPLAY` или `WAYLAND_DISPLAY`. Подробности: [BUILD.md](BUILD.md), [GUI_LINUX.md](GUI_LINUX.md).

## Консольный преобразователь

### Одна картинка

```bash
# PNG-превью: 3 × 2 карты, 384 × 256 блоков
./mapart -i photo.jpg -preset portrait -x 3 -y 2 -o output/art.png

# Превью и общая 3D-схема
./mapart -i photo.jpg -x 3 -y 2 -all-blocks \
  -o output/art.png -nbt output/art.nbt

# Плоская схема только из выбранных материалов
./mapart -i logo.png -x 1 -y 1 -build-mode 2d \
  -blocks white_wool,black_wool,red_wool -nbt output/logo.nbt

# Отдельная схема для каждой карты
./mapart -i photo.jpg -x 3 -y 2 -nbt-tiles output/art_tiles.zip
```

Если `-o` не задан, результат пишется в `output/<имя входного файла>.png`: например, `photo.jpg` → `output/photo.jpg.png`. Размер по умолчанию — 5 × 3 карты. Рядом с PNG сохраняется `_original.png`: исходник после геометрической подготовки, до цветовой обработки и подбора блоков.

### Пакетная обработка

```bash
./mapart -dir input -preset landscape -x 5 -y 3 -out-dir output/batch
./mapart -links links.txt -preset pastel -out-dir output/downloads
```

`-dir` обрабатывает поддерживаемые изображения непосредственно в выбранной папке, без вложенных каталогов. Формат `links.txt` — URL либо URL и размеры в картах:

```text
# Размеры из параметров команды
https://example.com/picture.png
# Индивидуальные размеры
https://example.com/portrait.jpg 3 4
```

Пакетные режимы сохраняют PNG. Для NBT используйте отдельный вызов с `-i` или `-qr`. Ошибка одного изображения не отменяет сохранённые результаты остальных; при наличии ошибок команда завершится с ненулевым кодом.

### Сравнение пресетов

```bash
./mapart -i photo.jpg -compare balanced,portrait,pastel -out-dir output/compare
./mapart -i photo.jpg -compare all -out-dir output/compare
```

Создаются изображения вариантов, JSON-настройки и HTML-страница сравнения. `-compare` работает с одним `-i`; вместо `-o` укажите `-out-dir`. Явные параметры и JSON-профиль применяются к каждому сравниваемому пресету.

### Профили и диагностика

```bash
./mapart -preset portrait -x 3 -y 4 -save-config portrait.json
./mapart -i photo.jpg -config portrait.json -strength 0.5 -o output/art.png
./mapart -preset portrait -show-config
./mapart -all-blocks -export-palette palette.json
./mapart -i photo.jpg -debug -o output/debug.png
./mapart -list-presets
./mapart -h
```

Приоритет настроек: **пресет → JSON-профиль → явно указанные флаги**. Значения `0` и `false` также переопределяют пресет. Булевый параметр отключается записью `-sky-cleanup=false`, а не отдельным аргументом `false`.

`-debug` дополнительно сохраняет подготовленное изображение, маску отключения дизеринга, её наложение, палитру и параметры. Профиль хранит настройки обработки, пути к маскам, выбранные блоки и режим 2D/3D. Он не встраивает изображения, ручные пиксельные правки, содержимое QR и настройки экспорта `supports`, `max-height`, `data-version`.

### Параметры CLI

| Задача | Параметры |
| --- | --- |
| Источник | `-i файл`, `-dir папка`, `-links файл.txt` или `-qr текст`; выбирается один режим |
| Вывод PNG | `-o файл.png` для одного изображения/QR; `-out-dir папка` для результатов |
| Размер | `-x N -y N`; каждая сторона 1–256 карт, всего не более 256 карт |
| Пресет и профиль | `-preset имя`, `-config файл.json`, `-save-config файл.json` |
| Геометрия | `-rotate 0/90/180/270`, `-flip-horizontal`, `-flip-vertical`, `-crop x,y,ширина,высота` |
| Вписывание | `-fit stretch` — растянуть; `contain` — сохранить пропорции с полями; `cover` — заполнить с обрезкой по центру |
| Масштабирование | `-resample nearest/bilinear/bicubic`; `-matte "#RRGGBB"` — цвет полей и прозрачности |
| Дизеринг | `-dither fs/ordered/none`, `-strength 0..1`, `-t порог`; `-t 0` снимает порог подавления ошибки |
| Подбор цвета | `-metric lab/rgb`; Lab использует CIEDE2000 |
| Цветокоррекция | `-brightness -100..100`, `-contrast 0.1..3`, `-saturation 0..3`, `-gamma 0.2..3`, `-temperature -100..100` |
| Детали | `-sharpen 0..2`, `-denoise 0..1`, `-auto-contrast`, `-monochrome` |
| Автомаски | `-background auto/off/color`, `-bg-color "#RRGGBB"`, `-bg-tolerance 0..150`, `-sky-cleanup`, `-clean-haze` |
| Ручные маски | `-no-dither-mask файл.png`, `-detail-mask файл.png` |
| Материалы | `-all-blocks`, `-terracotta`, `-natural-blocks`, `-blocks список_ID_через_запятую` |
| Своя палитра | `-palette файл.json` с массивом цветов `#RRGGBB`; для PNG |
| Постройка | `-build-mode 2d/3d`, `-supports=true/false`, `-max-height N`, `-data-version N` |
| Экспорт схем | `-nbt файл.nbt`, `-nbt-tiles файл.zip` |
| QR-оформление | `-qr-style square/rounded/dots`, `-qr-fg блок`, `-qr-bg блок`, `-qr-finder блок`, `-qr-logo файл`, `-qr-logo-size 5..20` |
| Сравнение | `-compare all` или имена пресетов через запятую |
| Справка и диагностика | `-h`, `-list-presets`, `-show-config`, `-export-palette файл.json`, `-debug` |
| Окно | `-gui`; принимает начальное изображение, профиль и настройки преобразования |

Поворот и отражения применяются перед обрезкой. Цвета с `#` и пути с пробелами заключайте в кавычки.

## Графический интерфейс

### Основной сценарий

1. Нажмите **«Открыть картинку…»** или перетащите файл в окно. Открытие файла запускает преобразование.
2. Выберите пресет и нажмите **«Применить»**. Простое выделение пресета показывает его описание.
3. Настройте размер, материалы, цвет и режим постройки, затем нажмите **«Преобразовать»**.
4. Сравните изображение с результатом и проверьте карту в игре, маску и материалы.
5. При необходимости откройте **«Редактор карты…»**, примените правки и сохраните PNG, NBT или ZIP.

Обработка выполняется в фоне, с индикатором состояния. Пока она идёт, настройки блокируются. После изменения параметров изображения экспорт отключается до следующего преобразования, чтобы не сохранить результат от старых настроек. Опоры, лимит высоты и DataVersion применяются при следующем экспорте схемы.

### Вкладки настроек

| Вкладка | Функции |
| --- | --- |
| **Блоки** | Автоматическая палитра или ручной выбор из 60 материалов; поиск по русскому названию и ID, фильтр группы, выбор шерсти/терракоты/всех блоков, снятие выбора, добавление или удаление выбранной группы |
| **Размер** | Ширина и высота в картах, stretch/contain/cover, nearest/bilinear/bicubic, координаты обрезки, цвет полей и прозрачности |
| **Дизеринг** | Floyd–Steinberg, ordered или none; сила и порог ошибки, Lab/RGB, приглушение цветных точек в дымке, нейтральная палитра |
| **Цвет** | Полный каталог блоков, добавление терракоты и природных материалов; яркость, контраст, насыщенность, гамма, температура, резкость, подавление шума и автоконтраст |
| **Маски** | Автоматическое определение ровного фона, отключение или поиск по цвету с допуском; маска светлого неба, загрузка ручных масок и своей RGB-палитры |
| **Постройка** | Плоская 2D или лестница 3D; опоры из булыжника, максимальная высота и DataVersion NBT |

Поиск и прокрутка списка блоков сохраняют скрытые отметки. **«Добавить группу»** и **«Убрать группу»** меняют только эту группу. В автоматическом режиме состав палитры определяется флажками на вкладке **«Цвет»**.

### Пресеты и JSON

**«Загрузить JSON…»** и **«Сохранить JSON…»** используют тот же формат, что и CLI. При применении пресета сохраняются размер, вписывание, обрезка, повороты, отражения, цвет полей, выбранные файлы масок/палитры, набор блоков и режим 2D/3D. Меняются параметры обработки изображения.

### Просмотр результата

| Вкладка | Что показывает |
| --- | --- |
| **Сравнение** | Исходник после геометрической подготовки и преобразованный мап-арт рядом |
| **Карта в игре** | Рассчитанное отображение карты с учётом высот схемы |
| **Маска фона** | Области, в которых подавляется дизеринг |
| **Материалы и размещение** | Размеры постройки, количество блоков и инструкции по размещению |

Флажок **«Размер 1:1»** показывает исходные пиксели с прокруткой. Уменьшенное превью сглаживается для просмотра; увеличение показывает пиксели чётко. Это не меняет экспорт. В Linux текст материалов также можно скопировать отдельной кнопкой.

### Редактор исходника

**«Редактор исходника…»** позволяет подготовить изображение до перевода в палитру:

- Выделить мышью прямоугольник обрезки или сбросить его.
- Повернуть изображение на 90° в обе стороны.
- Отразить по горизонтали или вертикали.
- Изменить яркость, контраст, насыщенность, гамму и температуру с обновлением предпросмотра.

**«Применить и преобразовать»** переносит настройки в основное окно и пересчитывает результат. **«Отмена»** закрывает редактор без применения изменений. Поворот и отражение сбрасывают прежнюю область обрезки.

### Редактор карты

**«Редактор карты…»** изменяет готовые пиксели после подбора блоков:

- **Кисть** размером 1, 3, 5, 9 или 17 пикселей/блоков, включая непрерывное рисование при перетаскивании.
- **Заливка** связанной области одного цвета.
- **Пипетка** для выбора существующего цвета.
- Палитра оттенков текущего набора материалов с названием блока и оттенка.
- **«Отменить»** и **«Вернуть»** для истории действий.
- Масштабирование колесом мыши, кнопками **+ / −**, выбором 25–3200% и режимом **«Вписать»**, с прокруткой увеличенного изображения.

Масштаб меняет только просмотр, размер кисти остаётся в блоках. После **«Применить правки»** пересчитываются схема, карта в игре и материалы; правки сохраняются при экспорте PNG/NBT/ZIP. Повторное преобразование исходника заменяет нарисованные пиксели новым результатом. JSON-профиль хранит настройки преобразования, а не рисунок редактора.

### Экспорт из окна

- **«Сохранить PNG…»** — мап-арт и соседний `_original.png`.
- **«Схема .nbt…»** — общая постройка, материалы CSV, параметры JSON и `_map.png`.
- **«ZIP по картам…»** — независимые схемы отдельных карт 128 × 128, списки материалов и описание разбиения.

Произвольная RGB-палитра позволяет сохранить PNG, но не определяет блоки для NBT. Ошибка построения, например превышение высоты, не мешает оценить PNG-превью.

### Генератор QR

Кнопка **«QR-код…»** открывает генератор со следующими настройками:

- Ссылка или произвольный текст; ширина и высота в картах.
- Плоская **2D** или лестница **3D**.
- Квадратные, скруглённые или круглые элементы.
- Раздельный выбор материалов для элементов, фона и трёх угловых маркеров.
- Необязательный логотип в центре, 5–20% ширины QR; выбор или удаление файла логотипа.

**«Обновить превью»** создаёт и проверяет QR в цветах Minecraft. **«Создать мап-арт»** переносит результат в основное окно для редактирования и экспорта. Программа проверяет чтение исходного текста, в том числе после применения ручных правок. Если код слишком плотный или оформление плохо читается, увеличьте число карт или измените цвета/стиль.

QR создаётся локально: программа не переходит по введённой ссылке. По умолчанию используется плоская карта 1 × 1 из белой и чёрной шерсти. Последнее применённое оформление хранится в текущем сеансе; ссылка и логотип не включаются в JSON-профиль обработки. Сохранённый `_original.png` позволяет позже открыть QR как обычное изображение.

CLI использует тот же генератор:

```bash
./mapart -qr "https://example.com" -o output/qr.png -nbt output/qr.nbt
./mapart -qr "https://example.com" -x 2 -y 2 -qr-style dots \
  -qr-fg blue_wool -qr-bg white_wool -qr-finder red_wool \
  -qr-logo logo.png -qr-logo-size 15 -nbt-tiles output/qr_tiles.zip
```

## Пресеты

| Пресет | Назначение |
| --- | --- |
| `balanced` | Настройки по умолчанию: Lab, умеренный дизеринг, автоматические маски |
| `portrait` | Портреты: мягкие переходы без автоматического отключения дизеринга на фоне |
| `pastel` | Пастельные градиенты: RGB, полное смешивание; возможна заметная зернистость |
| `landscape` | Пейзажи: RGB-смешивание без усиления резкости и автоматических масок |
| `night` | Тёмные сцены: небольшое осветление теней и смешивание переходов |
| `lineart` | Чёрно-белые рисунки: нейтральная палитра, автоконтраст, без дизеринга |
| `pixel` | Пиксель-арт: ближайший сосед, без дизеринга |
| `flat` | Иллюстрации с ровными заливками: автоматический фон и умеренное зерно |
| `clean-sky` | Светлое небо и дымка: подавление цветных точек; проверяйте бледные детали |

Пресет — отправная точка. Для плавных переходов попробуйте `pastel` или `portrait`; для зернистого фона уменьшите силу или задайте маску; для точного пиксель-арта используйте `pixel`. Пресет **`flat` не выбирает плоскую постройку**: режим 2D задаётся отдельно через `-build-mode 2d` или вкладку **«Постройка»**.

## Блоки, маски и режимы постройки

### Палитра

По умолчанию используются 16 цветов шерсти: 48 оттенков в 3D, 16 в 2D. `-terracotta` добавляет 16 цветов терракоты; `-natural-blocks` — ещё шесть материалов. `-all-blocks` включает весь встроенный каталог из 60 материалов: 60 базовых цветов для 2D и 180 оттенков для 3D. Явный `-blocks` ограничивает набор выбранными материалами.

Каталог не показывает блоки с дублирующими цветами карты. Старые профили с удалёнными именами переводятся на оставшийся материал того же цвета. Вода не включена: её оттенок требует отдельного расчёта глубины. Происхождение каталога и проверочные данные: [verification/block_catalog](verification/block_catalog/README.md).

### Маски

`-background auto` находит ровный фон, связанный с границами изображения; `color` использует заданный цвет и допуск; `off` отключает эту автомаску. `-sky-cleanup` подавляет дизеринг на светлом небе. Это маски обработки, а не удаление фона в прозрачность.

Белые области `-no-dither-mask` отключают дизеринг; белые области `-detail-mask` возвращают его для защищённых деталей. Маску деталей применяют последней. Маски могут иметь размер исходника или готового результата; маски исходного размера проходят соответствующее геометрическое преобразование.

### 2D и 3D

В **2D** поверхность плоская, используется один достижимый оттенок каждого блока. В **3D** высоты формируют три оттенка: тёмный, обычный и светлый. Схема включает северный служебный ряд, поэтому её размер по Z на один блок больше высоты изображения. Обычные опоры можно отключить `-supports=false`; требования отдельных материалов проверяются при экспорте.

Лимит высоты по умолчанию — **384 блока**. Если общая лестница его превышает, попробуйте `-nbt-tiles`: отдельные карты строятся независимо. DataVersion по умолчанию — **5023**, для которого в проекте подготовлен каталог Java 26.3. Вариант **3465** соответствует настройкам старого набора для Java 1.20.1; выбор DataVersion не делает новые блоки доступными в старой игре — несовместимые материалы отклоняются.

## Результат экспорта и использование схемы

При `-nbt output/art.nbt` создаются:

| Файл | Содержимое |
| --- | --- |
| `art.nbt` | Постройка в формате vanilla structure NBT, читаемом Litematica |
| `art_materials.csv` | Материалы, количество, полные стаки по 64 и остатки |
| `art_build.json` | Размеры, служебный ряд, смещение изображения и параметры размещения |
| `art_map.png` | Рассчитанный вид карты в игре |

ZIP содержит схемы отдельных карт, их материалы CSV, `layout.json` и `README.txt`. Это независимые постройки, а не части одной непрерывной лестницы.

Скопируйте `.nbt` в папку `schematics` игрового профиля и откройте через Litematica. Ориентируйте схему по указаниям `_build.json` и панели материалов: для оттенков важны север и юг. Границы карт масштаба 0 выровнены по координатам `X = -64 + 128k`, `Z = -64 + 128m`; учитывайте смещение изображения относительно служебного ряда.

Расчёт схем и цветов проверяется тестами и сохранёнными данными каталога. Это не автоматическая проверка постройки в запущенном Minecraft.

## Docker

Образ содержит CLI:

```bash
docker build -t mapart .
mkdir -p input output
# Сначала положите свою картинку в input/image.png.
docker run --rm -v "$PWD/input:/workspace/input:ro" -v "$PWD/output:/workspace/output" \
  mapart -i /workspace/input/image.png -o /workspace/output/art.png \
  -nbt /workspace/output/art.nbt
```

Примеры одиночной, пакетной и URL-обработки также есть в [docker-compose.yml](docker-compose.yml). При использовании Compose создайте собственный `links.txt` для профиля `links`.

## Разработка и проверки

```bash
make build-cli       # CLI
make build-gui       # Fyne GUI для Linux/macOS
make build-windows   # Windows GUI amd64
make pre-commit      # Проверка форматирования, go vet, короткие тесты
make test            # Все обычные тесты
make coverage        # Отчёт покрытия
go test -race ./...
go vet -tags gui ./...
go test -tags gui ./...
```

Тесты используют синтетические изображения и сохранённые JSON-данные каталога. Личные исходники, загруженные галереи, бинарники и результаты экспорта исключены из Git. Теги `internetreview` и `renderreview` включают дополнительные локальные проверки, для которых нужны отдельно подготовленные изображения.

GitHub Actions проверяет Linux, Windows и macOS, отдельно проверяет Linux GUI и собирает пакеты. Тег `v*` запускает создание **черновика** релиза с ZIP и SHA-256; публикацию выполняет владелец после проверки.
